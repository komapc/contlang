# Слепой тест кодирования

Проверяет, сохраняется ли смысл при цепочке *слово или предложение → код min-co → слово или предложение*, и сравнивает варианты языка (с корнем и без, с осью и без). Вызовы моделей делаются агентами (в Claude Code — инструментом Agent), всё остальное — скрипты.

## Протокол

1. **Пункты.** Список слов (`слово (часть речи) — русское пояснение`; пояснение обязательно для многозначных) или предложений:
   `python3 scripts/eval/prepare.py items data/eval/items/LIST.txt data/eval/runs/NAME --prefix w --chunk 46` (для предложений `--prefix s`). Появятся `items_w0.txt …` и `key.json`.
2. **Спецификации вариантов** (шаблоны `data/eval/templates/`, корни и оси из `roots.yaml`):
   ```
   python3 scripts/eval/prepare.py spec enc words data/eval/runs/NAME/spec_enc_full.md
   python3 scripts/eval/prepare.py spec dec words data/eval/runs/NAME/spec_dec_full.md
   python3 scripts/eval/prepare.py spec enc words .../spec_enc_abl.md --drop SIDE,HEAT
   python3 scripts/eval/prepare.py spec enc words .../spec_enc_ax.md --axis 'SEE=visibility: -5 hidden ... +5 bright'
   ```
3. **Кодировщики** (по одному агенту на вариант × кусок, лучше 2–3 независимых на условие, имя варианта `cond_A`, `cond_B`): читают только спецификацию кодировщика и `items_*.txt`, пишут `codes_<вариант>_<кусок>.md` (строка на пункт, та же нумерация).
4. **Декодеры:** читают только спецификацию декодера и `codes_*`, пишут `dec_<вариант>_<кусок>.md` (`лучшее | альт1, альт2` для слов, одно предложение для предложений). Оригинала не видят.
5. **Лист для судьи:** `python3 scripts/eval/judge_prep.py RUN words --key RUN/key.json --variants full,abl`. Печатает долю кодов с ошибками валидатора по вариантам (`scripts/mincode/validator.py`), пишет `judge_words.md` с перемешанными вариантами и `judge_map.json`.
6. **Судья** (агент другой модели, чем кодировщики, если возможно): читает только `judge_*.md`, пишет `scores_*.tsv` (`id<TAB>A<TAB>B…`). Шкалы: слова 0–3 (3 слово или синоним в данном смысле, 2 среди альтернатив, 1 рядом, 0 мимо); предложения 0–3 (3 тот же смысл, 2 главное сохранено, 1 только тема, 0 мимо).
7. **Результат:** `python3 scripts/eval/score.py --map RUN/judge_map.json --scores RUN/scores_words.tsv --base full`. Таблица по вариантам и разница с 95%-ным бутстреп-интервалом по пунктам.

## Как читать

- Меняем язык (добавляем или убираем корень, ось, метку) только если интервал разницы не содержит 0 или если вариант проще при той же точности (удаление).
- Шум между прогонами порядка ±0,3 на 34–60 пунктах; больше пунктов и несколько кодировщиков сужают интервал.
- Пункты, на которых правили рецепты, нельзя использовать как проверку: для проверки нужен отложенный набор (`data/eval/items/holdout_*`, пока не создан).
- Тексты, которые модель знает наизусть (декларация прав, известные статьи), заражают тест: кодировщик-декодер может вспоминать, а не раскодировать.

## Сохранённые прогоны

`data/eval/runs/ablation3` (без `CONTAINER`, `MAYBE`, `SIDE`: 164 слова и 60 предложений) и `data/eval/runs/see_axis` (ось видимости у `SEE`, 34 слова). Их цифры воспроизводятся командой из п. 7 (тест `tests/test_eval.py`).
