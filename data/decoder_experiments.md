# Математический кодер и декодер: опыты 2026-10

Вопрос: может ли математика без языковой модели закодировать слово корнями min-co и восстановить его обратно — хотя бы в правильное смысловое поле — так, чтобы код оставался читаемым человеком.

**Протокол для всех таблиц.** Собственный круг математики: слово → код (перебор корней) → декодер → место слова среди 10 721 слова словаря сайта. Слова — частые слова словаря сайта; слова-полюса корней исключены; имена собственные исключены (слово должно быть в `/usr/share/dict/words` строчными или в `data/wordlist_en_x5.tsv`). Рецепты как мерило не используются: это коды, написанные людьми и моделями и проверенные малыми слепыми тестами, а не истина. Без языковой модели: только numpy (и WordNet для пар слов). Словарь корней — обученный (45 корней), если не сказано иное.

Скрипты — `scripts/experiments/decoder/`, запускать из корня репозитория; промежуточные файлы пишутся рядом со скриптами (в git не входят). Цепочка: `r4.py` (коды 10 000 слов) → `r4an.py`, `r4b.py` (разбор) → `r5.py` (кодер с проверкой декодером) → `r9.py`, `r10.py`, `r11.py` (пары слов).

## 1. Декодеры

| декодер | как оценивает слово |
| :-- | :-- |
| сумма | cos(слово, y), y — сумма корней кода |
| CSLS | 2·cos − hub; hub — средний cos слова с его 10 ближайшими из 3000 случайных кодов (слова-хабы близки к любому коду) |
| «И» | мягкий минимум z-оценок близости слова к каждому корню отдельно: −log Σⱼ exp(−2zⱼ) / 2 |
| смесь | ½ z(CSLS) + ½ «И» — на сайте по умолчанию |

## 2. До 3 и до 4 корней (`r4.py`, `r4an.py`, `r4b.py`; 8421 слово)

| корней | сумма top1 | смесь top1 | смесь top3 | смесь top10 |
| :-- | --: | --: | --: | --: |
| ≤ 3 | 7,3% | 49,9% | 75,6% | 93,1% |
| ≤ 4 | 13,4% | 63,8% | 86,2% | 96,4% |

Худшие слова — коды из одного корня: *basketball, football* → `FIGHT(=-2)`, *journal* → `TEXT`, *shin* → `BODY`. Дальше — религия (*rabbi, bishop, monastery*) и деньги (*pesos, euro, mortgage*).

**Смысловое поле.** Первая догадка — само слово или одно из его 20 ближайших соседей: смесь 76,5%, сумма 35,8%. cos(догадка, слово) < 0,3: смесь 17,4%, сумма 48,7%; медиана cos 0,97 против 0,31.

## 3. Кодер с проверкой декодером (`r5.py`)

Из 40 лучших по cos кандидатов (лучшие уровни для каждой комбинации корней и главного) берётся тот, что смесь ставит выше всего.

| корней | top1 | top3 | top10 | худшее место |
| :-- | --: | --: | --: | --: |
| ≤ 3 | 84,1% | 94,5% | 98,9% | 101 |
| ≤ 4 | 90,1% | | | |

Сумме не помогает. Цена — читаемость: часть кодов становится паролем (*pesos* = `MEASURE(=+2) THING(=-2) SOMEONE(=+1)`). На сайт не перенесён.

## 4. Корень SPIRIT (`spirit4.py`, `spirit5.py`)

Ось + *spiritual religious sacred holy divine* / − *materialistic worldly mundane earthly material*. Полюса берутся из полного Numberbatch: в словаре сайта нет *materialistic, worldly, mundane, earthly*, и без них полюс «−» сводился к *secular*, а *islamist, fundamentalist* получали минус.

| вариант | общие 800 слов, top1 | религия (43), top1 / top3 / медиана | материальное (14), top1 |
| :-- | --: | :-- | --: |
| без корня | 39,0% | 21% / 33% / 8 | 50% |
| SPIRIT с осью | 39,5% | 30% / 49% / 4 | 43% |
| SACRED без оси | 38,9% | 33% / 47% / 4 | 50% |
| случайный корень (контроль) | 40,0% | 21% / 30% / 7 | 50% |

Места слов: monastery 191 → 5, rabbi 134 → 9, mosque 71 → 4, priest 52 → 2, church 15 → 1. Край «−»: *material, petty, stuff, plastic, trash, goods*. Ближайшие оси: ART 0,19, NEAR 0,18. Предложенная шкала: −5 вещное … −3 мелочное … 0 … +3 религиозное … +5 святое. Не введён: ждёт слепого теста.

## 5. Вес корня как вторая ось (`r6.py`, 3000 слов)

Каждому корню, кроме значения, свободный вес {1; 0,6; 0,3} («насколько важен», как в geek code): top1 56,8% против 52,9% при весах по позиции (декодер — смесь с «И» по позициям), с 4 корнями — 66,1%. Вес обратно связан с |значением| (−0,40): математика использует «малый вес при крайнем значении» как оттенок без области.

## 6. Порядок корней (`r7.py`, `r7b.py`, `r8.py`)

Сейчас порядок для математики — только вес главного корня 1 против 0,6. Варианты:

| схема | top1 | перестановка 1↔2 теряет 1-е место |
| :-- | --: | --: |
| A — как сейчас | 52,9% | 26% |
| M — у модификаторов центр × 0,25, ось сохраняется («главный — область, модификаторы — оттенок») | 56,5% | 60% |
| M + убывающие веса 1 / 0,6 / 0,36 | 57,3% | |

При M порядок несёт смысл: `PLACE CONSUME` → *restaurant* (*eat* на 200-м месте), `CONSUME PLACE` → *eat* на 4-м. Ролевые корни главными при M вредят (`SOMEONE FIGHT` — *soldier* на 244-м), но исключение «роли никогда не главные» не помогло.

С переобучением словаря под каждую схему (`r8.py`, 1500 слов вне обучения):

| схема | словарь из полюсов | обученный |
| :-- | --: | --: |
| A | 45,7% | 47,2% |
| M | 50,7% | 49,7% |
| M + роли | 47,1% | 47,2% |

M помогает; исключение для ролей отвергнуто; обучение словаря для смеси почти ничего не даёт.

## 7. Два слова вместо одного кода (`r9.py`, `r10.py`, `r11.py`)

Если код не ставит слово первым — слово передаётся парой слов «главное + уточнение» (как смихут, прилагательное + существительное, наречие + глагол). Каждое слово пары — «хорошее»: его собственный код смесь раскодирует первым, так что читатель получает оба слова точно. Читатель ищет слово, близкое к обоим (то же «И» + CSLS, главное с весом 1, уточнение 0,6); сами части и однокоренные цели исключены. Проверка — 1339 слов из 8421, которые кодер с проверкой декодером (≤ 3 корня) не ставит первыми.

| как выбирается пара | проверено | top1 | top3 | top10 | всего по 8421 слову первым |
| :-- | --: | --: | --: | --: | --: |
| один код (для сравнения) | 1339 | 0% | 66% | | 84,1% |
| любая пара из 60 ближайших хороших (`r9.py`) | 1339 | 100% | | | 100% |
| главное — гипероним по WordNet (3 значения, до 3 уровней вверх), уточнение — не синоним и не из ветки главного (`r10.py`) | 1204 | 76,7% | 85,7% | 91,8% | 95,1% |
| то же, только первое значение в WordNet (`r11.py first`) | 1110 | 61,4% | 73,7% | 82,2% | |
| то же, первое значение и главное среди 300 ближайших к цели (`r11.py near`) | 809 | 83,1% | 95,3% | 99,0% | 92,1% |
| три значения и главное среди 300 ближайших (`r11.py near3`, до правила имён) | 1037 | 87,7% | 95,8% | 99,1% | 94,9% |
| то же + правило имён (`r11.py near3`) | 1016 | **86,4%** | 95,7% | 99,1% | **94,5%** |

Где проверено меньше 1339, у остальных слов нет подходящего главного слова в словаре; они остаются с одним кодом.

- Свободная пара (`r9.py`) «триангулирует» любое слово, но это не смихут: *garlic* = *potatoes* + *pepper* (соседи по полке), *ban* = *prohibit* + *embargo* (два синонима).
- Гипероним даёт структуру: *fish* = *food* + *shark*, *beans* = *vegetable* + *coffee*, *petroleum* = *fuel* + *refinery*, *devil* = *spirit* + *snake*, *cathedral* = *building* + *parish*, *polynomial* = *function* + *math*, *lyrics* = *poem* + *vocals*.
- «Только первое значение» вредит: первым в WordNet часто стоит не то значение, что в векторе (*west* → *object* + *southward*, место 1371).
- Фильтр «главное среди 300 ближайших» убирает случайные гиперонимы из чужих значений (*strait* = *situation* + *sea*, *transfers* = *action* + *exchange*).
- Имена собственные протекают в векторы: *mainland* = *land* + *tang* (династия), *west* = *direction* + *newton*, *more* = *person* + *tougher* (Томас Мор в WordNet). **Правило имён:** часть пары отбрасывается, если среди 20 её ближайших соседей не меньше 30% имён собственных (*tang* 100%, *newton* 95%, *marched* 50% — месяцы; у хороших уточнений 0–15%), а значения-имена в WordNet (instance) не дают главного слова. Стоит 1,3 пункта; *mainland* = *earth* + *shipments*, *west* = *direction* + *sunset*. Не ловит ассоциации через названия команд: *angels* = *soul* + *inning*, *saints* = *god* + *players*.
- Человеческие кеннинги не обязательно работают: *dig* + *tool* → *drill, hammer*; *house* + *book* → *books, library*; *vegetable* + *smell* → *garlic* на 2-м месте. Векторы складывают ассоциации, а не строят определение.
- Словарь сайта мал и новостной: нет *onion, spice, shovel, allium*. Расширение — отдельное решение (размер vocab.bin на сайте).

## Что не измерено
