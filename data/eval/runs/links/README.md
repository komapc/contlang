# Связки между существительными: PI / FROM / FOR / LIKE

Вопрос: читаются ли пары `X | o СВЯЗКА Y | o` лучше, если вместо одного общего `PI` есть связки с одним смыслом каждая, и выбор между ними задан порядком вопросов.

Определения (`make_specs.py`, раздел LINKS в `spec_enc_*.md` / `spec_dec_*.md`). Первое слово X — всегда род, второе Y только сужает его. Кодер задаёт вопросы по порядку и берёт первую подходящую связку:

1. `FROM` — X сделан из Y («drink FROM apple» = cider, «house FROM ice» = igloo);
2. `FOR` — X сделан для Y: им пользуются с Y, на Y или Y («tool FOR hair» = comb, «container FOR flowers» = vase);
3. `LIKE` — X похож на Y, но не Y («fish LIKE sword» = swordfish, «insect LIKE stick» = stick insect);
4. `PI` — всё прочее: X — часть Y, или X находится или живёт в Y («seed PI fruit» = pip, «edge PI river» = riverbank).

Слушатель читает каждую связку одним способом: из / для / похож на / часть или в.

- **Варианты:**
  - A — только PI (спецификация как в `../pi_for`);
  - B — FROM, FOR, PI;
  - C — FROM, FOR, LIKE, PI;
  - D — коды кодеров C, где все связки заменены на PI; читаются по спецификации A. Это чистое сравнение со связками и без, на одних и тех же кодах.
- **Слова (20, по 5 на задуманную связку):**
  - FROM: wine, paper, cheese, leather, candle;
  - FOR: key, lid, saddle, wallet, sheath;
  - LIKE: starfish, seahorse, jellyfish, catfish, sunflower;
  - PI: roof, petal, hoof, nest, yolk.
  Второе слово — только из корней, без кавычек (`task_enc_*.md`).
- **Кодеры:** по 2 Haiku на вариант (`enc_*.md`).
- **Листы** (`make.py`, seed 11): на листе 10 целей одного кодера и 4 наполнителя. 16 листов, по 2 декодера Haiku на лист, запуск из нейтральной папки. Ответы — `dec_NN_[ab].md`.
- **Оценка:** `sem.py`, таблицы — `sem.md`.

| **C — FROM/FOR/LIKE/PI** | **46/80** | **51/80** | **0,71** | **0,76** |

Слово первым по группам:

| группа | A | B | C | D |
|---|--:|--:|--:|--:|
| FROM | 8/20 | 12/20 | 12/20 | 6/20 |
| FOR | 11/20 | 8/20 | 13/20 | 8/20 |
| LIKE | 6/20 | 4/20 | 9/20 | 6/20 |
| PI | 7/20 | 8/20 | 12/20 | 11/20 |

- **Сами связки несут смысл.** Те же коды с FROM, FOR и LIKE читаются первым словом 46 раз из 80, с одним PI — 31 раз из 80. Выигрыш виден в группах FROM (+6), FOR (+5) и LIKE (+3). У группы PI коды почти не менялись, и там без разницы (12 и 11) — это контроль.
- **Вариант B (без LIKE) не лучше A.** FROM в нём помог (cheese 4/4), но кодеры B хуже написали FOR-слова (key читается как screw, lid как ceiling). Слова LIKE пришлось писать через PI, и они читаются хуже всего (4/20). Кодеров всего два на вариант, поэтому разница A/B/C — это и разница кодеров. Чистое сравнение — только C против D.
- **Решились связкой** (C, 4/4 или почти): sheath (D — pocketknife), sunflower, candle, lid, wallet, paper, cheese.
- **Не решились:**
  - starfish прочитана как sunfish: «похож на солнце» вместо звезды, корня для звезды нет;
  - catfish прочитан как jellyfish или eel;
  - yolk прочитан как embryo;
  - saddle прочитано как stable: главное слово `PLACE DO` читается как место.
  Это ошибки корней и главного слова, а не связки.
- **Математика** (`scripts/site/eval_math.js`) пока знает только PI и FOR. FROM и LIKE для неё — неизвестные корни, поэтому векторами этот тест не проверялся.

В `roots.yaml` связки не добавлены: решение за автором языка.
