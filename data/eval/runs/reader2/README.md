# Кодер, выбирающий код моделью читателя (2026-10-14)

Пороги — [dec.md](dec.md) (закоммичен до листов). 150 новых слов (`test_words.json`, ранг 300–6000, не читались раньше).
- **M** — код сайта (база + метки, один смысл).
- **P20 / P80** — модель читателя v2 (`choose.py`, обучена на 4787 прошлых прочтениях) выбирает код из 20 / 80 лучших по cos
  кандидатов (`cand.js`, topr 12) и кода сайта.

9 слепых читателей Haiku (слово в трёх вариантах у разных читателей), 3 судьи Haiku 2/1/0, `run.py readers|pairs|merge|score`.
Судья пропустил одну строку: «123. 1» (wounded — treated) вписано вручную.

## Почему (без читателей)
- `pairs_check.py`: из пар кодов одного слова с разными оценками cos математики выбирает лучший лишь в 32 %, модель читателя — в 57 %.
- `exp.py`: признаки «голова × корень», «корень × знак» — AUC до 0,78, пары до 62 %; плато.
- `specread.py`: «буквальный читатель» по словам-полюсам спецификации — AUC 0,64, пары 42 %.
- Строение кода: у математики 3 корня в 3189 из 3527 прочтений; «близко» при 1 / 2 / 3 корнях — 69 / 35 / 22 %;
  нули: 26 → 20 → 16 % при 0 / 1 / 2 нулевых значениях. Внутри слова лучший код чаще короче и без нулей
  (пары математики: меньше нулей — 59 %, меньше корней — 54 %).
- `select_model.py` (на `readings_all.json` = прошлые + 450 прочтений этого теста): условный логит по парам с признаками
  корни, нули, слабые |v| ≤ 1, ср. |v|, cos модели, cos математики. Проверка по словам: пары 69 % (все), **59 % на парах математики** —
  столько же, сколько одна модель читателя. Строение поверх модели ничего не добавляет: модель его уже учитывает.

Вывод: выбирать среди кодов, близких по вектору, — потолок около +5 %. Нужен другой кодер (меньше корней, без нулей по построению),
а не другой отбор.
