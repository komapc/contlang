# Слепой тест: читаются ли коды самопроверки лучше (2026-10-13)

Вопрос: самопроверка кодера (../selfcheck) даёт векторам +198 первыми на 2000 слов. Читают ли такие коды лучше модели?
- `make.js`: 100 случайных слов из «других 1000», у которых коды различаются (624 из 1000). A — код без самопроверки, B — с самопроверкой (голова та же, штраф 0,5). Без пары PI. Часть речи — преобладающая по WordNet.
- Читатели — Haiku по `dec.md` (`prepare.py spec dec words`), по 50 кодов, по два независимых читателя на вариант, каждый в своей папке: `a/ans_K_R.md`, `b/ans_K_R.md`.
- `score.py` → `score.txt`: место первого ответа с синонимами WordNet (как ../verbs).

| | место (геом. среднее) | первым | в тройке |
|---|--:|--:|--:|
| A без самопроверки | 172 | 12/200 | 18/200 |
| B самопроверка | 194 | 12/200 | 20/200 |

B / A = 1,13 (95 % 0,84–1,51): разницы нет. Прирост для векторов в читаемость моделями не переходит.

Обе версии читаются плохо (6 % первыми): коды случайных слов строятся по побочным связям векторов (dolphins → `THING(=+2) GRAIN(=-5)` «газ, дух», street → `NEAR(=+5) THING(=-1) INSIDE(=-5)` «оболочка»), в выборке есть имена (jakarta, monroe). Иногда короче лучше (engineer: `ART(=-3) SEX(=+3)` → engineer, obstacle), иногда хуже (flame `HEAT(=+3)` → warmth, suspect, atmosphere).
Решение: самопроверка на сайте выключена (коды хуже на вид, пользы читателям нет).
