# Раунд 2: key через door / lock / open

Вопрос: читается ли key как «орудие · дверь/замок/открывать», и как в языке читаются door, lock, open сами по себе.

- Кодеры: 2 агента Haiku (`enc_A.md`, `enc_B.md`). Задание в `task_enc.md`: door ×4, lock ×4, open ×3, key ×6 (два слова через PI). К ним добавлены два моих варианта key: `… PI DO(=+5) JOIN(=+5) CAN(=-3)` и `DO(=+5) | o PI <door2>`.
- Листы (`make.py`, `sheet_NN.md`, `key.json`): на листе по одному варианту key, door, lock, open и 6 наполнителей. Второе слово ключа на том же листе отдельно не встречается.
- Декодеры: 2 Haiku на лист, запуск из нейтральной папки. Спец: `../key_furniture/spec_task_dec.md`, в задании допускается глагол для `| i`. Ответы лежат в `dec_NN_[ab].md`.
- Оценка (`sem.py`, полный Numberbatch): cos первого ответа и лучший cos из трёх, среднее по декодерам. Таблицы в `sem.md`.

## Итог

- **key решается**: `DO(=+5) BIG(=-4) | o PI PART(=-2) PLACE SIDE(=+5) | o` («маленькое орудие · проём в стене»). Ответы двух декодеров: «door key | key, doorknob» и «doorknob | key, latch». В обоих key есть среди трёх ответов, первый ответ в среднем 0,57. Дверь на том же листе была в другом, нечитаемом варианте, так что код не подсказан соседями. Проверка всего на одном листе (2 декодера).
- Без «маленького» (`DO(=+5) | o PI …`) читается просто door: cos к key 0,26–0,30.
- «Орудие · замок / скреплять» во всех вариантах даёт staple, nail, pin, clip (0,13–0,24). «Орудие · открывать / разъединять» даёт knife, coin, microchip (≤0,15). Замок вторым словом не помогает.
- **door** = `PART(=-2) PLACE SIDE(=+5) | o`: entrance 4/6, front 2/6, cos 0,50. Варианты с INSIDE дают room, с JOIN(=-5) — island, core.
- **lock** = `DO(=+5) JOIN(=+5) CAN(=-3) | o` («скрепляющее орудие, которое не даёт»): lock 3/4, cos 0,84. Остальные варианты дают clamp, bolt, fastener, glue, а с PLACE — bridge.
- **open** не читается ни в одном варианте: cut, insert, extract (≤0,12). Слова со смыслом «открыть» среди корней нет.
