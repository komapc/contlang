# «Два слова»: пара от модели, коды — математикой (2026-10-13)

Вопрос: если модель подбирает пару «род + уточнение» (`X LINK Y`), а математика кодирует каждое слово, читается ли это лучше одного кода?
- `make1.js`: 100 случайных существительных из «других 1000» (не имена, не множественное, часть речи o) → words.txt, gen/words_K.md.
- Пары: два Haiku по `gen/task.md` → gen/pairs_K.md (`N. X | LINK | Y`), например pianist — musician FOR keyboard, chapel — building FOR prayer.
- `make2.js` → items.json и списки кодов. A — один код слова; B — `код(X) | o LINK код(Y) | o` (10 пар со словом не из словаря — код A);
  C — сайт (`Reader.encode`: код или код PI сосед); D — сама пара словами (потолок идеи без потерь кода).
- Слепые читатели Haiku: по 2 на вариант и половину (16 запусков), A–C по `dec.md`, D по `dec_d.md`. `score.py` → score.txt (место с синонимами WordNet).

| | место (геом. среднее) | первым | в тройке |
|---|--:|--:|--:|
| A один код | 203 | 10/200 | 22/200 |
| B пара модели кодом математики | 313 | 9/200 | 20/200 |
| C сайт (код / PI сосед) | 160 | 11/200 | 26/200 |
| D пара модели словами | 5,5 | 103/200 | 135/200 |

B / A 1,54 (95 % 1,03–2,31) — хуже; C / A 0,79 (0,60–1,05); D / B 0,02.

Вывод: сама идея пары отличная (словами — половина слов первыми), но математика губит её на кодах самих слов пары,
даже самых простых: person → `RULE(=-1) MANY(=+2) FRIEND(=+3)`, building → `INSIDE(=0) NEAR(=+4) GRAIN(=+3)`,
water → `THING(=-1) GRAIN(=-5) HEAT(=-3)`, part → `PART(=-1) BEGIN(=+2) DO`. Две неточности складываются.
Родовых слов мало (person 8 раз, part 5, place 3 …) — им можно дать коды из таблицы.
