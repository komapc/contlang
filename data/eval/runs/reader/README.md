# Модель читателя и судья

Цель — мерить не «место», а **близко ли первый ответ** к слову (то же смысловое поле), и найти дешёвую замену слепым читателям.

- `collect.py` → readings.json: все прошлые чтения одного кода (15 вариантов × 100 слов × 2 читателя).
- Судья: слепой Haiku оценивает пары «слово — первый ответ» (2 близко, 1 рядом, 0 мимо), без указания варианта.
  `judge_make.py`, `judge_new.py` (новые пары и `--merge`), labels.json. Согласие судей на 60 повторах: «близко» да/нет 88 %.
- `labels.py`, `compare.py` — доля «близко» по вариантам и парные сравнения по словам.

| вариант | близко |
|---|--:|
| H код модели | 38 % |
| B модель выбирает из 8 кодов математики | 26 % |
| M, MZ, N, S, SZ, T, B5, TZ, GTS | 18–24 % |
| A нынешняя математика | 17 % |
| B3 | 14 % |

## Модель читателя (замена читателям) — не получилась

Корреляция внутри слова (какой из кодов одного слова прочтётся лучше) с оценкой судьи; потолок (согласие двух читателей) ≈ 0,87.

| | внутри слова | сито по вариантам (Спирмен) |
|---|--:|--:|
| цель кодера математики cos(y, x) | **−0,07** | |
| читатель по подписям шкал spec.md (`lib.gloss`) | 0,10 | −0,45 |
| обученный (гребневая, остаток над подписями, `learn.py`) | 0,20 | −0,24 |

Собственная цель кодера — близость суммы к вектору слова — **слегка обратна** успеху чтения. Поэтому кодеры «подгони сумму» упираются,
а SZ, который сумму не подгоняет, — лучшая математика. Векторные модели читателя не упорядочивают даже кодеры — нужны настоящие читатели.

## Знаки значений (`signs.py`, `values.py`, `cn_probe.py`)

Знак модели (H, |v| ≥ 3, 113 случаев) против:
- проекции на ось math.json: |z| < 1 — 61 %, 1–2 — 82 %, ≥ 2 — 94 %;
- подписей шкал spec.md: 73 % (центрированно 71 %) — векторы сглаживают антонимы;
- прямых связей ConceptNet слова со словами полюсов: покрытие 28 %, совпадение 31/32; с синонимами полюсов (WordNet) 36 %, 85 %.
- Правило `values.value` (ConceptNet → |z| ≥ 1,5 → ConceptNet с синонимами → иначе голый корень): покрытие 56 %, совпадение 92 %.
