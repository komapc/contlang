# Заранее (2026-11-07, до кодов): коды пишет модель «с умом»; словосочетание одним словом — только если так понятнее

Основание: [../phrases2](../phrases2/README.md) — свёртка по правилам не помогла, потому что не читается код самого слова;
[../big1000](../big1000/result.txt) — коды модели читаются вдвое лучше кодов математики (51 % против 24 %): у математики не тот
главный корень (людей она пишет через RULE/SEX вместо SOMEONE), всегда 3 корня, слабые значения, нет ролей.
**По указанию пользователя (2026-11-07) в этом тесте кодирует модель, а не математика сайта.**
Вопросы пользователя: 1) насколько лучше коды «с умом»; 2) словосочетание одним словом — не всегда, а только если так лучше.

**Фразы** (`make.py`): 120 = 60 из ../phrases (устойчивые и свободные; имена и фразовые глаголы) + 60 из ../phrases2
(свободные: степень, пустой глагол, признак-сдвиг, независимый признак). Группы: fixed_n, fixed_v, free_n, free_v, deg, light, axis, indep.

**Варианты**:
- **A** — математика сайта пословно (коды из ../phrases и ../phrases2, без изменений);
- **M2** — модель, всегда пословно: каждое английское слово — своё слово min-co, главное первым;
- **M1** — модель, всегда одно слово min-co на всю фразу;
- **MC** — модель выбирает сама: одно слово, если так читатель вернее восстановит смысл, иначе пословно.

Кодировщики — Sonnet (`Agent`, model sonnet), отдельные агенты на каждый вариант (по 2 на вариант, по 60 фраз), видят только фразу,
спецификацию кодировщика сайта (`ENC_SPEC` без её заголовка) и `writer_task_*.md`; ни ответов читателей, ни других вариантов.
Коды проверяются правилами языка (`check.mjs` → worker/check.js); неверный код возвращается тому же кодировщику на одну правку,
что останется неверным — читается как есть.

**Чтение и судья**: 16 слепых Haiku — 4 варианта × 2 половины × 2 читателя, у каждого 60 кодов одного варианта (порядок перемешан),
`DEC_SPEC` без её задания + `reader_task.md` (одинаковое для всех, примеры не из списка фраз). Варианту A — новые читатели,
чтобы все варианты читались в одних условиях. Судья — слепой Haiku по `judge_task.md` (как в ../phrases), пары «фраза — первый ответ»
без указания варианта; оценки уже известных пар берутся из ../phrases и ../phrases2.
Мера — доля первых ответов «близко» (2), среднее по 2 читателям, бутстрап по фразам (5000, seed 0); для сведения — «близко или рядом».

**Главный критерий**: MC − A на всех 120 ≥ +10 п. п. и нижняя граница 95 % > 0 → коды «с умом» лучше математики.

**Выбор «одно слово, только если лучше»** (вопрос 2) считается подтверждённым, если MC не хуже обоих принудительных вариантов
(MC − M1 ≥ 0 и MC − M2 ≥ 0 по точечной оценке) и на фразах, где M1 и M2 читаются по-разному, MC выбрал лучший из двух
способов чаще чем в половине случаев. Для сведения: M2 − A (модель против математики при одинаковом пословном виде),
M1 − M2 по группам, доля свёрнутых в MC по группам, «оракул» max(M1, M2) по фразе.

**Прогнозы** (записаны заранее):
- пользователь: MC лучше всех — свёртка там, где лучше, и пословно там, где лучше;
- Claude: MC − A ≈ +20…30 п. п.; M1 лучше M2 на устойчивых (fixed), M2 не хуже M1 на свободных; MC около лучшего из M1/M2,
  но различие с ним в пределах шума; выбор верен примерно в 55–60 % спорных фраз.

Оговорки: кодировщик — сильнее читателя (Sonnet пишет, Haiku читает); один и тот же кодировщик не повторяется — разброс между
кодировщиками не оценивается; n = 15 в группе — внутри группы значим только большой эффект.
