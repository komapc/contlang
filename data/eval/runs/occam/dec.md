# Заранее (2026-10-14, до листов): экономный кодер — меньше корней, без нулей у не главных

Основание (../reader2/README.md): при равной модели читателя более точная подгонка вектора читается хуже (вес cos математики −0,50
в select_model.py); у математики почти всегда 3 корня, у кодов LLM — чаще 2. Пары внутри слова дают лишь 54 % (корни) и 59 % (нули):
это ставка примерно 50 на 50.

- **M** — код сайта (база + метки, один смысл).
- **O** — тот же кодер и вектор смысла, но из всех наборов корней (1–3 из topr 12, `cand.js`) берётся max cos − λ·(k − 1),
  наборы с нулём у не главного корня с осью исключены. λ = 0,045 — наименьшее из сетки 0,005, при котором на 230 доступных
  словах 3 корня у ≤ 30 % кодов (как у кодов LLM); правило, не подгонка по прочтениям (`occam.py`).
- Слова: новые из ../reader2/pool_words.json, без прочитанных, без шума и имён, по одной форме на базу; в тест — 150 случайных
  из тех, где O ≠ M (163 из 230). O: 1 корень у 51, 2 — у 94, 3 — у 5.

Слово в двух вариантах — у разных читателей (6 слепых Haiku по 50 кодов, DEC_SPEC), судья Haiku 2/1/0. Мера — доля первых ответов
«близко», бутстрап по словам. **Успех: O − M с нижней границей 95 % > 0** → перенести правило в math.js (решение за пользователем).
Иначе гипотеза «меньше корней / без нулей» отвергнута. Для сведения: по частям речи, по числу корней у O, «рядом».
