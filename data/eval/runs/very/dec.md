# Заранее (2026-11-07, до кодов): как писать «очень» — метка, значение оси или отдельное слово

Вопрос пользователя: «оптимальный подход к "очень"». Сейчас в языке три способа сказать степень:
метка интенсивности `I` (`I+4` very), значение оси главного корня (`HEAT(=-5)` против `HEAT(=-3)`), отдельное слово-наречие.
Раньше: метка `I` читалась в 18 из 24 прочтений (roundtrip_degree, без контроля); phrases3 — модель пословно часто писала
«очень» меткой сама; phrases2 — свёртка по правилам не помогла, но там не читался сам главный код (математика).

**Слова**: 12 прилагательных — cold, happy, tired, fast, big, angry, old, hungry, dangerous, expensive, quiet, strong;
4 степени — barely (1), slightly (2), very (4), extremely (5); без слова степени — 3. Итого 48 фраз + 12 простых слов.

**Коды** (`make.py`): один Sonnet пишет код каждого прилагательного (одно слово; главный корень со значением оси модуля 3)
и каждого наречия степени отдельно (слово `| e`). Варианты строятся из этих кодов правилом, без модели:
- **I** — код прилагательного + метка `I` (barely −5, slightly −2, very +4, extremely +5; по спецификации);
- **X** — модуль значения главного корня = степень (1, 2, 4, 5; знак сохраняется), без метки;
- **IX** — и то, и другое;
- **W** — два слова: код прилагательного, затем код наречия степени (пословно, как M2 в phrases3).
Простые слова (степень 3) во всех вариантах одинаковы — для калибровки читателей.

**Чтение**: по 2 слепых Haiku на вариант, каждый — все 60 кодов своего варианта вперемешку; спецификация читателя сайта
без её задания + `reader_task.md`: прочтение (выражение) и степень 1–5 (1 barely … 3 без слова степени … 5 extremely).
**Судья** Haiku 2/1/0: близко ли прочтение к прилагательному по смыслу, степень не учитывать (`judge_task.md`).

**Меры** на 48 фразах со степенью, среднее по 2 читателям, бутстрап по фразам (5000, seed 0):
степень — доля точных попаданий и средняя ошибка |ответ − цель|; смысл — доля «близко».

**Главный критерий**: рекомендовать вариант с наибольшей долей точной степени, если он лучше W (отдельное слово, то, что
делает пословный кодировщик без правила) на ≥ +15 п. п. с нижней границей > 0 и не хуже W по смыслу больше чем на 10 п. п.
Иначе — правило не нужно, пусть кодировщик пишет как хочет.

**Прогноз Claude**: I лучше всех по степени (≈ 60 %), X хуже всех (very и extremely сливаются, слабые значения читаются как
другое слово), IX ≈ I, W ≈ 40 %; смысл у всех близок, у X ниже.
