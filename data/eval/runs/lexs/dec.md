# Заранее (2026-11-10, до кодов и чтений): lexs — помогает ли проверенный словарь в предложениях (пилот)

Основание: [lex](../lex/README.md), [lex2](../lex2/README.md) — выбор кода слова по слепому чтению даёт +24 п. п. на словах, где
выбор меняет код; но слова там читались отдельно. В предложениях (pipe, conj) ошибка почти всегда в содержательном слове.
Решение пользователя 2026-11-10: на сайте кодирует модель (gpt-5-mini, один проход). Вопрос: если дать ей проверенные коды
слов предложения, станет ли предложение понятнее?

Пилот — **верхняя граница**: словарь покрывает все содержательные слова предложений (в жизни — около половины: 2000 частых
слов покрывают ~55 % словоформ), и смысл слова взят из контекста (оракул).

**Предложения**: 120 новых из Brown (`pick.py`: фильтры pipe, по 12 из 10 жанров, seed 20261110, без предложений pipe).
**Слова**: Sonnet выписывает содержательные слова (лемма, часть речи, смысл в этом предложении, `extract_task.md`);
одинаковые лемма + часть речи — одна статья (`lemmas.json`).

**Кандидаты** на каждую статью (`cands.json`):
- **G1, G2** — gpt-5-mini, режим encode воркера (`w/`, как на сайте), ввод `lemma (pos: gloss)`, два независимых вызова;
- **S1, S2** — Sonnet, задача и спецификация lex (`../lex/writer_task.md`, ENC_SPEC), два независимых кодировщика.
Неверный код Sonnet возвращается на одну правку.

**Выбор** (без людей и без Haiku — дешёвая модель, офлайн): gpt-5-mini читает каждый код вслепую 3 раза (DEC_SPEC,
пачки по 20 одного варианта, случайный порядок), судья gpt-5-mini 2/1/0 (как в lex). Чтения 1–2 — выбор: у статьи
берётся кандидат с наибольшим числом «близко» (2), затем по сумме, при равенстве порядок G1, G2, S1, S2 (`pick.json`).
Чтение 3 — проверка выбора на свежем чтении.

**Стоп-кран** (до предложений): выигрыш выбора на чтении 3, доля «близко» выбранного кода − G1, по всем статьям.
Если < +8 п. п. — стоп, предложения не кодируются (эффект в предложениях не будет виден).

**Предложения**: gpt-5-mini, один проход (ENC_SENTS + задача кодирования PR #19, без чтения и правки):
- **M0** — без словаря;
- **MG** — со словарём из кодов G1 (собственные коды модели, посчитанные отдельно — контроль «словаря как такового»);
- **ML** — со словарём выбранных кодов.
Словарь — строки `lemma (pos) = CODE` для слов этого предложения. Читают по 2 новых слепых Haiku на вариант (D0 как в pipe,
по 60 предложений на читателя); судьи Sonnet (`../pipe/tasks/judge.md`, 0–3). Бутстрап по предложениям (5000, seed 0).

**Критерии**:
1. ML − M0 ≥ +0,20 и нижняя граница 95 % > 0 → проверенный словарь помогает в предложениях: рекомендую строить словарь
   частых лемм (2000–5000) этим способом (решение пользователя).
2. Для сведения: MG − M0 (сам словарь), ML − MG (выбор); доля слов словаря, взятых в код дословно; нарушения правил.

**Прогнозы** (Claude): выигрыш выбора на чтении 3 ≈ +10 п. п.; ML − M0 ≈ +0,15; MG − M0 ≈ +0,05.
