# PI против FOR: новая связка «для чего»

Вопрос: если уточняющее слово — то, чему предмет служит (key ← дверь, saddle ← лошадь), читается ли пара лучше через отдельную частицу `FOR`, чем через общее `PI`?

`FOR` в пробной спецификации (`spec_enc_F.md`, `spec_dec_F.md`): «X FOR Y» = X, которым пользуются с Y, на Y или для Y (примеры в спеке: comb, vase, glove — не цели). `PI` остаётся для принадлежности, части, места и материала. Вариант P — прежняя спецификация с одним PI.

- Слова (16): key, lid, saddle, leash, pillow, wallet, nest, kennel, cork, sheath, collar, hive, stable, shoelace, frame, cradle (`task_enc_P.md`, `task_enc_F.md`).
- Кодеры: по 2 Haiku на вариант (`enc_P_a/b.md`, `enc_F_a/b.md`). Кодеры F поставили FOR во всех 32 кодах.
- Листы (`make.py`, seed 5): 8 листов, на листе 8 слов одного кодера и 4 наполнителя. Листы 1–4 — P, 5–8 — F. Декодеры: 2 Haiku на лист, запуск из нейтральной папки, каждый видит только свою спецификацию и лист. Ответы — `dec_NN_[ab].md`.
- Оценка: `sem.py` (полный Numberbatch), таблицы — `sem.md`.

## Итог

| вариант | слово первым | среди трёх | cos первого ответа | лучший cos из трёх |
|---|--:|--:|--:|--:|
| P (PI) | 22/64 | 34/64 | 0,54 | 0,67 |
| F (FOR) | **37/64** | **41/64** | **0,71** | **0,75** |
| наполнители | 36/64 | 47/64 | 0,77 | 0,85 |

- С FOR цели читаются почти так же, как однословные наполнители. Сильнее всего выросли lid (ceiling/hood → lid 4/4), wallet (0,10 → 0,82), sheath, saddle, cradle и pillow.
- Хуже с FOR читаются nest (birdcage) и frame (lens, easel). cork не читается в обоих вариантах.
- Уточнение названием вида ("Canis", "Equus") работает с любой связкой: kennel, leash и stable — 4/4 в обоих вариантах.
- **Оговорка:** кодеры F писали свои коды целиком, а не меняли одну частицу (у lid, например, другое второе слово). Поэтому разница — между вариантами языка, а не только между частицами. Чистая проверка — те же коды с заменой PI ↔ FOR.
- Математика (векторы и граф ConceptNet, `scripts/site/eval_math.js --graph`) разницы между PI и FOR почти не видит (docs/math.md, раздел 9).

В `roots.yaml` FOR не добавлен: это решение за автором языка.
