# Перенос кодов модели в математику (2026-10-13)

Пункт 2 после ../twowords3: коды, написанные моделью, читаются в 2,3 раза лучше кодов математики. Можно ли научить
словарь корней так, чтобы математика сама писала коды «как модель»?

- `fit.js`: коды моделей считаются верными, центры C и оси A корней подбираются гребневой регрессией, чтобы эти коды
  раскладывали векторы слов (`min ‖MΘ − T‖² + lam‖Θ − Θ0‖²`, T = |MΘ0|·x, как scripts/18_sparse_learn.py), затем нормировка
  и возврат по дуге к нынешнему словарю (cos ≥ tau), затем (`--perc=E,eta`) пакетный перцептрон: если кодер выбрал не
  код модели, атомы кода модели тянутся к x, выбранного — от x. Обучение: 318 одиночных кодов без ролей —
  site/data/recipes.json (192) и коды Haiku из ../twowords3/write (126); 100 тестовых слов ../twowords2 исключены отовсюду.
- Мера без читателей — совпадение набора корней с кодом модели (Жаккар), на отложенных обучающих (5 частей) и на
  тестовых (код H ../twowords3, 72 слова без ролей):

| | отложенные | тест |
|---|--:|--:|
| нынешний словарь | 0,33 | 0,28 |
| lam 30, tau 0,85 | 0,37 | 0,32 |
| lam 3, tau 0,5 | 0,41 | 0,34 |
| lam 3, tau 0,5 + перцептрон 3 × 0,02 (выбран) | 0,42 | 0,36 |
| то же, только коды Haiku (126) | 0,34 | 0,33 |
| на самих обучающих словах | 0,71 | — |

  Рост с объёмом данных — около +0,03 на удвоение (¼ данных 0,35, ½ 0,36, ¾ 0,39, все 0,41).
- `make.js` → коды тех же 100 слов кодером с новым словарём (dict.json), как вариант A; 4 слепых Haiku (n/);
  счёт — `DISTILL=1 ../twowords3/score.py` → score.txt.

| | место (геом.) | первым | в тройке |
|---|--:|--:|--:|
| A нынешний кодер | 142 | 12/200 | 30/200 |
| B модель выбирает из 8 кодов математики | 128 | 20/200 | 35/200 |
| **N кодер с перенесённым словарём** | **127** | 15/200 | 31/200 |
| H код пишет модель | 60 | 38/200 | 58/200 |

N / A 0,89 (95 % 0,57–1,38) — не значимо; H / N 0,47 (0,26–0,85).

Правило, заданное до теста: если N / A ≈ 0,9 и интервал захватывает 1 — линейной модели корней не хватает ёмкости,
и покупать данные (≈1000 кодов Haiku) не стоит: по кривой это даст совпадение около 0,45, а не уровень H.
Коды стали осмысленнее (person `SOMEONE(=+1) SAME(=-2) LIVE(=0)`, road `PLACE LONG(=-2) MOVE(=0)`, chapel
`PLACE INSIDE(=+2) SAY(=-1)`), но читаются почти как прежние. Словарь сайта не меняется.

Не учтено: роли (agent, tool …) математика не выражает вовсе, а у модели они в 28 кодах из 100; мера сравнивает только
наборы корней, не значения; для сайта новый словарь потребовал бы пересчёта hub, rootZ, mix (build_math.py) и круга математики.
