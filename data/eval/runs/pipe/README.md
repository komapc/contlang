# pipe: многопроходный кодировщик предложений — результат (2026-11-07)

Заранее: [dec.md](dec.md) (с дополнением до holdout). Предложения Brown (`pick.py`, `sents.json`): dev 30, holdout 60.
Все проходы — отдельные агенты Sonnet; читатели — слепые Haiku (и Sonnet для проверки); судья Sonnet 0–3 сравнивает
прочтение с исходным предложением. Промпты — `tasks/`, все входы и ответы — `dev/`, `holdout/` (`codes/`, `answers/`, `judge/`).

## Варианты

- **E0** — один проход: предложение → код (как сейчас).
- **ES** — упростить → закодировать.
- **E1** — упростить → расставить `{}` (что одно слово, что разбить) → закодировать по скобкам.
- **E1V** — E1 → слепой читатель читает код обратно (значение каждого слова и предложение) → правщик видит
  упрощённое предложение, код и прочтение и правит то, что прочитано не так.
- **E0V** (только holdout, разведка) — E0 → чтение → правка, без упрощения и скобок.
- Декодеры: **D0** — сразу предложение; **D1** — сначала значение каждого слова, потом предложение.

## Итог

**Holdout (60 предложений, главный критерий, D0):**

| кодировщик | среднее /3 | ≥ 2 |
|---|---|---|
| E0 | 1,03 | 20 % |
| E0V | 1,35 | 25 % |
| **E1V** | **1,48** | **37 %** |
| E0, читатель Sonnet | 1,03 | 25 % |
| E1V, читатель Sonnet | 1,70 | 55 % |

- **E1V − E0 = +0,44 [+0,25 … +0,65] → главный критерий выполнен** (порог +0,25, нижняя граница > 0).
- Читатель другой модели (Sonnet) видит тот же выигрыш, даже больше: +0,67 [+0,43 … +0,90]. Правка подгоняла коды под Haiku,
  но это не подгонка под одного читателя — коды стали понятнее вообще.
- E0V − E0 = +0,32 [+0,12 … +0,51]; E1V − E0V = +0,12 [−0,02 … +0,28] — упрощение и скобки поверх проверки добавляют
  немного, на грани шума.

**Dev (30, все варианты):** E0 1,08; ES 1,23; E1 1,13; **E1V 1,72**. ES − E0 +0,15 [−0,10 … +0,42], E1 − ES −0,10,
**E1V − E1 +0,58 [+0,37 … +0,82]**; D1 − D0 ≈ 0 у всех кодировщиков. Итоги — `dev/result.txt`, `holdout/result.txt`.

## Что это значит

1. **Работает петля «написать → дать прочитать вслепую → исправить».** Это и есть «многопроходность», которая даёт выигрыш.
   Кодировщик не видит, как его поймут; одного взгляда на чужое прочтение хватает, чтобы исправить корни, роли и частицы.
2. **Упрощение и скобки сами по себе почти ничего не дают** (dev: +0,15 и −0,10, оба в шуме). Прогноз (упрощение +0,3 —
   главный вклад; проверка +0,1–0,2) **не сбылся**: вышло наоборот.
3. **Почему скобки не помогли**: проход 2 не группировал, а дробил. Слов на 30 предложений dev: E0 128, ES 187, E1 266,
   E1V 232 (holdout: E0 249, E1 431, E1V 449, E0V 340). Служебные слова стали отдельными словами (`{since} {then}`),
   кодировщик честно закодировал каждое — и предложение рассыпалось на 9 слов, которые читаются по отдельности, а не вместе.
4. **Ошибки упрощения неисправимы дальше**: правщик сверяется с упрощённым предложением, судья — с исходным.
   Пример: *practically all bees and bumblebees hibernate* → «все пчёлы, кроме медоносной, и почти все большие пчёлы спят…».
5. **Декодер в два шага (D1) не нужен**: на dev ни у одного кодировщика не лучше D0.
6. **Потолок всё ещё низкий**: даже у E1V «тот же смысл» (3) — 3 % у Haiku и 17 % у Sonnet. Главная потеря — отдельные
   понятия, для которых нет хорошей комбинации корней (*architect*, *partition*, *pall of dust*), и идиомы.

Проверка судьи (dev): прочитаны пары, где E1V ≥ 2 и E0 ≤ 1 — высокие оценки заслужены
(*Martin called for patience…* → E1V «Martin said to the Americans: stand still and be calm!», E0 «a careless setback is
found among his compatriots»); длинные расплывчатые прочтения судья не награждает.

## Оговорки

- Один кодировщик на вариант (дисперсия кодировщиков не измерена); правщик — Sonnet, как и кодировщик.
- В воркере читать обратно будет та же дешёвая модель, что и кодирует (gpt-5-mini), а не Haiku — выигрыш там надо проверить.
- Цена: E1V — 5 вызовов модели на предложение, E0V — 3 (почти тот же выигрыш).

## Предложение (решает пользователь)

Режим «предложение» в воркере: кодировать → прочитать вслепую → исправить (E0V, 3 вызова), с опцией упрощения перед этим
(E1V, ещё 2 вызова; без скобок — они дробят). PR с реализацией — отдельно, без слияния.
