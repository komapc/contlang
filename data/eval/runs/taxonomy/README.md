# Род по таксономии и проверка диагноза «дело в выборе корней» (2026-10-13)

- `anchors.py`: полюса спецификации как узлы WordNet (person → SOMEONE, animal → `THING(=+4)`, plant → `THING(=0)`,
  liquid / body_of_water → `GRAIN(=-3)`, illness → BODY, event → HAPPEN, device → `ART(=-5)`, container → `INSIDE(=+5)` …, 64 узла).
  Главный корень слова — ближайший такой узел среди гиперонимов первого смысла → heads.json (род есть у 84 из 100).
- `make.js` → T: главный корень и значение из таблицы, до 2 уточнений подбирает математика (`Coder.top(…, head)`);
  без рода — код A. M (диагноз): корни и порядок из кода модели H, значения подбирает математика по cos.
- Слепые Haiku, 2 на половину (t/, mr/), `TAX=1 ../twowords3/score.py` → score.txt:

| | место (геом.) | первым | в тройке |
|---|--:|--:|--:|
| A сейчас | 142 | 12/200 | 30/200 |
| T род по таксономии | 134 | 9/200 | 24/200 |
| M корни модели, значения математики | 122 | 26/200 | 40/200 |
| H код модели | 60 | 38/200 | 58/200 |

T / A 0,95 (0,66–1,37); M / A 0,86 (0,50–1,48); **H / M 0,49 (0,31–0,76)**.

Диагноз «дело только в корнях» неверен: те же корни, что у модели, со значениями математики читаются вдвое хуже.
`signs.js` → signs.txt: из 123 ненулевых значений модели знак совпал у подбора M в 65 %, у «измерения» (z-оценка проекции
слова на ось a_r по словарю) в 74 %, у измерения по толкованию в 71 %. Модель ставит ±5 там, где |z| около 1: значения
математики не только слабые, но и в трети случаев с другим знаком (homer GOOD +4 / −5, employee RULE +4 / −4).

`ROOT(=0)`: у математики 25 из 260 значений, и это центр корня (корень вообще), а по спецификации (=0) — середина оси
(THING(=0) растение, GRAIN(=0) порошок, FIGHT(=0) ссора); у модели — 6 из 129, почти всё `GIVE(=0)` (обмен).
