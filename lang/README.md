# Версии языка

Репозиторий держит несколько версий min-co рядом. Версия — это набор языковых файлов; инструменты берут версию явным
аргументом (`--lang <id>`), без аргумента — v1. Пути разрешает `scripts/mincode/spec.py` (`spec.paths(id)`, `spec.versions()`).

| id | статус | где лежит | что развёрнуто |
|---|---|---|---|
| **v1** | min-co 1.0, рабочая; тег `minco-1.0` | `roots.yaml`, `phonetics.yaml` в корне; шаблоны спецификаций `data/eval/templates/`; приёмы `data/site/tips_short.md`; документы `docs/` | сайт minco.lipu.dev, воркер, `docs/`, скилл `mincode` |
| **v2** | min-co 2.0, в разработке (с 2026-11-10) | `lang/v2/`: `roots.yaml`, `templates/`, `tips_short.md`; хартия [`charter.md`](v2/charter.md), разбор корней [`roots_audit.md`](v2/roots_audit.md) | ничего |

## Состав версии

| файл | зачем | обязателен |
|---|---|---|
| `roots.yaml` | корни, оси, метки, роли, частицы, лимиты — источник правды | да |
| `templates/` | шаблоны спецификаций кодировщика и читателя (`core.md`, `enc_*.md`, `dec_*.md`) для слепых тестов | да, чтобы собирать спецификации |
| `tips_short.md` | краткие приёмы кодирования для модели | нет |
| `phonetics.yaml` | звучание корней | нет (фонетика — в последнюю очередь) |
| `README.md` или `charter.md` | откуда ответвлена, цели, отличия | да |

## Что умеет работать с любой версией

- `scripts/mincode/validator.py --lang <id> FILE...` — проверка кодов по правилам версии;
- `scripts/eval/prepare.py spec enc|dec words|sents OUT.md --lang <id>` — спецификация для слепого теста;
- `spec.load(version=<id>)` в своих скриптах.

Только v1 (пока версия не принята): `scripts/mincode/gen.py` (`docs/tables.md`, `docs/lexicon.md`), сборка сайта и воркера
(`scripts/site/`), `worker/check.js`, ранние скрипты `scripts/01_…`–`23_…`. Если новая версия меняет синтаксис кода
(не только корни), ей понадобится свой валидатор — заводится тогда же.

## Как завести новую версию

1. `mkdir lang/<id>` и скопировать набор файлов версии-родителя (v1 — из мест в таблице выше). id — метка, не номер:
   соседние варианты одной версии — `v2a`, `v2b`.
2. Первой строкой `README.md` или `charter.md`: «ответвлено от <родитель>, коммит <hash>».
3. `.venv/bin/python -m pytest tests/test_versions.py` — версия грузится, валидатор создаётся, спецификации собираются.

## Прогоны

Каждый прогон в `data/eval/runs/` пишет в `dec.md`, на какой версии языка он сделан (`язык: v2`), и кладёт к себе
собранную спецификацию: версия в разработке меняется, а прогон должен остаться воспроизводимым.

## Когда версия принимается

Перенос версии на сайт и в воркер, а также перенос файлов v1 из корня в `lang/v1/` — отдельные решения пользователя.
